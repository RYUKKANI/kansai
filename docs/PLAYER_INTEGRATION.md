# 후속 선수 관리 프로그램 연동 계약

홈페이지를 다시 만들지 않고 후속 프로그램을 연결하기 위한 명세입니다.
출석·평가·건강 관리 UI와 내부 API 전체는 이번 버전의 구현 범위가 아닙니다.

## 선수 식별자

players.id는 UUID이며 등록 후 변경할 수 없습니다. 이름·등번호·포지션이 바뀌어도 유지합니다.
공개 프로필은 public_player_profiles.player_id, 경기 기록은 match_events.player_id,
출석은 private.attendance.player_id, 평가는 private.player_evaluations.player_id로 같은 선수를 참조합니다.
이름이나 등번호로 기록을 결합하거나 UUID를 재사용하지 않습니다.

## 공개 승인 흐름

1. 내부 프로그램은 선수 UUID와 내부 정보를 관리합니다.
2. 공개할 항목만 골라 공개 프로필 초안을 등록합니다.
3. 공개 이름·영문 이름·등번호·포지션·소개·사진·활동 상태·표시 순서를 검토합니다.
4. Owner 또는 Administrator가 공개를 승인합니다.
5. 홈페이지는 발행된 프로필의 허용 필드만 읽습니다.

내부 변경이 공개 프로필을 자동으로 덮어쓰지 않습니다.
Coach는 초안·승인 대기를 저장하고 공개 승인은 할 수 없습니다.
연락처·비상 연락망·출석·평가·컨디션·건강·지도진 메모는 공개 프로필에 추가하지 않습니다.
동의 철회 시 비공개로 전환합니다. 재구축과 캐시는 정적 배포의 반영 절차를 따릅니다.

## 공개 API

간사이 프로젝트의 /rest/v1/에 publishable key로 요청합니다.
행과 컬럼 권한은 익명 RLS와 GRANT가 제한합니다.

| 리소스 | 공개 필드 |
| --- | --- |
| articles | slug·제목·요약·본문·분류·사진·발행일 |
| public_player_profiles | player_id·slug·공개 이름·등번호·포지션·소개·사진·활동 상태·순서 |
| fixtures | 대회·상대·장소·시간·상태·결과·리포트 |
| media_assets, media_albums | 공개 사진·영상·앨범·설명·촬영일 |
| site_pages | 구단 소개·참가 안내 |

승인 담당자 UUID, 내부 선수 이름과 동의 메모, 훈련 메모, 감사 로그는 익명 응답에 포함하지 않습니다.
기사와 프로필의 slug는 첫 발행 뒤 고정됩니다.

## 내부 API의 확장

private 스키마는 Data API에 노출하지 않고 현재 모든 클라이언트 접근을 차단합니다.
후속 프로그램은 Auth 사용자와 업무 범위를 확인하는 서버/Edge Function을 통해 접근합니다.
서버가 service key를 사용할 때도 호출자의 역할과 선수 UUID·허용 필드 목록을 다시 확인해야 합니다.
브라우저에 비밀키를 넣거나 private 전체 테이블 권한을 여는 방식으로 연결하지 않습니다.

권장 요청은 player_id, 변경할 공개 필드, 마지막으로 읽은 updated_at입니다.
버전이 다르면 충돌로 반환해 운영자가 다시 확인합니다. 재전송은 요청 UUID로 중복을 방지합니다.
담당 선수 범위·동시 수정·요청 중복 처리는 후속 내부 API에서 구현합니다.
현재 웹 관리자는 마지막 저장이 우선하며, UUID와 최초 공개 URL의 불변성은 DB에서 보장합니다.
