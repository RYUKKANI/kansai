# 이메일 없는 관계자 계정 운영 — 2026-10-16

## 사용자 흐름

- 로그인은 아이디와 비밀번호만 사용합니다.
- 가입 항목은 아이디, 비밀번호·확인, 실명, 소속·담당 업무, 내부 실명 표시·작업 기록 안내 확인입니다. 이메일을 입력받거나 확인 메일을 보내지 않습니다.
- 새 계정은 승인 대기입니다. 최고 관리자(Owner)가 기존 구단 연락 수단으로 본인·실명·로그인 아이디와 관계자 여부를 확인하고 역할을 지정합니다. 승인 전에는 본인 상태만 조회할 수 있습니다.
- 일반 계정의 아이디 확인·비밀번호 재설정은 Owner의 멤버 관리에서 처리합니다. 비밀번호 원문은 조회할 수 없으며 새 비밀번호만 설정합니다.
- 유일한 Owner가 접근을 잃은 경우 기존 기기 결합 복구 요청을 사용합니다. 프로젝트 관리자가 기존 계정과 요청 번호·기기 확인 번호를 대조한 뒤 승인하며, 요청만으로 권한이나 비밀번호가 바뀌지 않습니다.

## 인증과 데이터 보존

비밀번호 저장·검증은 기존 Supabase Auth를 계속 사용합니다. 네이티브 Auth의 이메일 식별자 칸에는 신규 계정에 한해 서버가 `crypto.randomUUID()`로 생성한 `staff-UUID@accounts.kansai.invalid`를 넣습니다. 이는 수신 가능한 연락 주소가 아니라 서버 전용 기술 식별자입니다. 로그인 아이디에서 유도하지 않으며, 사용자가 제출하는 가입 `email` 필드는 거절합니다.

이 기술 식별자는 가입 응답·명부·본인 신청 상태·관리자 연락처에 표시하지 않습니다. 사용자의 네이티브 Auth 세션에는 Auth 자체의 식별자 필드가 존재할 수 있으며, 실제 이메일이나 구단 권한을 뜻하지 않습니다. `email_confirm`은 네이티브 비밀번호 로그인을 가능하게 하는 내부 상태이며, 별도의 구단 승인이나 이메일 소유 확인으로 취급하지 않습니다.

기존 계정의 이메일·UUID·비밀번호·권한·실명·콘텐츠·작업 이력은 일괄 변경하지 않습니다. 기존에 발급된 복구 링크를 즉시 무효화하지 않도록 안전한 콜백 검증과 서버 호환 경로는 유지하되 새 이메일 발송 양식·버튼·이메일 초대는 제공하지 않습니다. 기존 이메일 확인 정책 계정은 종전 DB 정책을 따릅니다.

아이디 정규화·DB 고유 제약, 승인·역할·MFA·현재 세션 검사, 마지막 활성 Owner 보호, CAPTCHA 정책, 공통 생성 한도와 아이디·검증된 IP별 제한을 유지합니다. 무작위 기술 주소를 시도 제한의 식별자로 사용하지 않습니다. 비밀번호·토큰·비밀키는 별도 테이블이나 감사 이력에 저장하지 않습니다.

## 변경·검사·반영

DB migration `20261016073919_staff_opaque_auth_address_contact.sql`은 기존 단일 신청 연락처 RPC에서 기술 주소를 `email:null`, `contact_available:false`로 반환하도록 제한합니다. 실제 이전 연락 주소의 Owner 전용 조회와 기존 함수 ACL은 유지합니다. 테이블·기존 행·권한의 초기화나 일괄 갱신은 없습니다.

검사 항목은 이메일 없는 가입 요청과 네이티브 Auth 생성 계약, 제출 이메일 거절, 기술 주소 비노출, 승인 전 RLS, 관리자 승인·비밀번호 관리, 기존 복구 콜백과 기기 복구, 다국어·입력 보존입니다. `npm run check`, `npm run build`, `npm run export:preview`, 전체 SQL/JS와 활성 로그인 빌드 검사를 실행합니다. 실제 GoTrue·Mailpit CI는 새 가입의 메일 발송 없음과 아이디 로그인·승인 대기 차단을 검사하며 기존 UUID 계정의 복구도 별도 확인합니다. 구체적인 최종 실행 결과와 배포 버전은 PR에 기록합니다.

검증된 같은 Git 트리의 CI 성공 후 DB 연락처 제한 → Edge 가입 경로 → 화면 순서로 반영합니다. 운영에서 실계정 가입·실명·비밀번호를 시험 값으로 바꾸지 않습니다. 반영 전후 계정·권한·자료·감사 집계를 비교합니다.

화면 또는 Edge 장애 시 직전 검증 버전으로 되돌릴 수 있습니다. 이미 생성된 무메일 계정의 UUID와 비밀번호 검증은 이전 아이디 로그인에도 호환되며, 이메일 없는 계정은 Owner 관리로 복구합니다. 연락처 비노출 DB 제한은 유지하고 자료를 삭제하거나 기존 계정을 재가입시키지 않습니다.
