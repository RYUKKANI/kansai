## 로그인과 초대

관리자 주소는 https://ryukkani.github.io/kansai/admin/입니다.
최초 로그인은 초대 메일의 확인 링크를 열어 이메일 소유를 확인합니다. 초대만 받은 계정에는 비밀번호가 없습니다.
그 뒤 초대된 이메일로 메일 링크를 이용해 로그인합니다. 이미 비밀번호를 설정한 계정은 비밀번호 로그인도 가능합니다.
초대 메일을 찾지 못하거나 만료된 경우 ‘メールのログインリンクを送信’을 누릅니다.
미인증 계정의 OTP 요청에서 `signup_disabled`가 반환되면 기존 계정에 확인 메일을 다시 보냅니다.
`auth.resend({ type: 'signup' })`는 새 계정을 만들지 않습니다. 전송 접수는 로그인 완료를 뜻하지 않습니다.
메일 링크의 복귀 주소는 관리자 페이지로 명시하며, 사용자 인증 뒤 활성 DB 역할을 다시 확인합니다.
일반 회원가입과 익명 로그인은 끄고 이메일 확인은 유지합니다.
Site URL은 홈페이지, 추가 redirect URL은 관리자 주소로 제한합니다.

최초 Owner는 Supabase Auth에서 초대한 뒤 그 Auth UUID를 admin_roles에 등록합니다.
자신을 Owner로 만드는 공개 API는 없습니다. 이후 초대와 역할 변경은 Owner 메뉴에서 처리합니다.
탈퇴한 운영진은 역할을 비활성화하고 세션을 해지합니다.

Supabase 기본 메일 전송은 수신자·횟수 제한이 있으므로 여러 운영진을 초대할 때 메일 설정을 확인합니다.
외부 SMTP를 연결할 경우 사용자가 계정과 비용을 결정합니다. 전송 오류를 초대 완료로 표시하지 않습니다.

Free 플랜에서는 유출 비밀번호 차단 기능을 사용할 수 없어 Auth 보안 점검에 경고 1건이 남습니다.
이 기능은 Pro 이상에서 제공됩니다. 요금제를 변경하지 않고 초대 전용 로그인과 이메일 확인을 유지합니다.
기능 제공 조건은 [Supabase 공식 문서](https://supabase.com/docs/guides/auth/password-security)에서 확인할 수 있습니다.

## 콘텐츠와 이력

초안, 승인 대기, 발행을 구분합니다. 발행한 항목을 초안으로 돌리면 공개를 취소합니다.
정적 홈페이지는 다음 재구축 뒤 반영됩니다. 사진과 앨범이 필요하면 먼저 해당 미디어를 발행합니다.
선수 프로필은 UUID에 연결하고 Owner/Administrator가 승인합니다.
선수의 공개 동의를 철회하면 프로필은 DB에서 비공개로 바뀝니다.

변경 이력은 주체·테이블·항목·작업·변경된 필드 이름·시각을 남깁니다.
감사 로그에는 개인정보나 본문 전체를 복제하지 않습니다. V3 콘텐츠 복구는 기사·미디어·앨범·구단 안내의 내용을 별도 비공개 이력으로 보관하고 화면에는 최근 90일/항목별 30개를 표시합니다. 원본 이력은 자동 삭제하지 않습니다. 선수·연락처·출석·평가 자료는 이 대상이 아닙니다.
선수와 운영진은 삭제 대신 상태를 변경해 기존 UUID를 유지합니다.

## 백업과 검증

무료 프로젝트의 자동 백업을 전제로 하지 않습니다.
운영 담당자가 암호화된 저장 위치와 보관 기간을 정하고 DB 덤프와 미디어를 백업합니다.
비공개 선수 기록을 GitHub나 공개 Actions artifact에 넣지 않습니다.

마이그레이션 파일 버전은 원격 기록과 일치시키고 실행한 파일은 변경하지 않습니다.
DB 변경은 새 마이그레이션으로 추가하고 권한 검사를 통과한 뒤 적용합니다.
npm test는 메모리 PostgreSQL 권한과 빌드 UI를 검사합니다.
실제 DB 검사는 supabase/tests/remote-permissions.sql로 실행하고 반드시 ROLLBACK합니다.
공개 API 검사에는 publishable key만 사용하며 Supabase Advisors에서 보안 상태를 확인합니다.
