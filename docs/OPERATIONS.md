## 로그인과 가입

관리자 주소는 <https://kansaiunited.com/admin/>입니다.
로그인은 아이디와 비밀번호를 사용하며 가입 화면은 이메일을 입력받지 않습니다.
신규 관계자는 실명·담당 업무와 안내 확인을 제출하고 승인 대기 상태로 생성됩니다.
Owner가 구단의 기존 연락 수단으로 본인과 관계자 여부를 확인한 뒤 승인하고 실제 역할을 부여합니다.
승인 전에는 본인의 신청 상태만 조회할 수 있습니다.

비밀번호 저장·검증과 기존 UUID는 Supabase Auth가 담당합니다. 자체 비밀번호 테이블을 만들지 않습니다.
공개 Auth 직접 가입은 `auth.enable_signup=false`로 차단하고, 서버 `staff-auth`의 제한·승인 절차를 거칩니다.
호스팅 설정의 `Allow new users to sign up`은 끄되 Email 제공자는 켜 둡니다.
`auth.email.enable_signup=true`는 이메일/비밀번호 제공자를 유지하는 CLI 설정이며 공개 가입 허용과 다릅니다.
확인 메일 정책은 기존 계정용으로 유지합니다. 새 무메일 계정의 기술 식별자는 사용자의 연락 주소가 아닙니다.
자세한 계정·기기 복구 절차는 [이메일 없는 관계자 계정 운영](STAFF_NO_EMAIL_20261016.md)을 따릅니다.

Owner의 멤버 관리에서 아이디·이름·비밀번호 재설정을 처리합니다. 저장된 비밀번호 원문은 조회할 수 없습니다.
멤버 관리는 로그인 아이디 또는 실명을 입력해 검색한 뒤 결과에서 계정을 선택합니다.
검색 전에는 계정별 관리 양식을 표시하지 않습니다. 동명이인은 함께 표시되는 로그인 아이디로 구분하고,
선택한 계정의 승인·등급·실명 확인·선수 연결·실명 정정 신청을 해당 관리 영역에서 처리합니다.
아이디·실명을 바꿔도 선택 대상은 계정 UUID로 유지합니다. 관리 영역을 닫거나 다시 검색하면 이전 편집창을 폐기합니다.
검색 조건은 URL이나 브라우저 저장소에 보관하지 않습니다. 검색은 Owner 업무의 표시 방식이며,
실제 접근과 변경 권한은 기존 서버·RLS 검사가 담당합니다.
기존 계정을 삭제하거나 재가입시키지 않으며 계정 정지는 현재 DB 역할·승인·세션 검사에 즉시 반영됩니다.
마지막 활성 Owner는 제거·강등할 수 없습니다. 유일한 Owner의 접근 복구는 기기 결합 요청과 프로젝트 관리자의 확인을 거칩니다.
이번 보안 적용에는 새 2단계 인증 등록·강제를 포함하지 않습니다. 이미 등록된 인증 수단에 대한 기존 검사는 유지합니다.

일반 관리 화면은 URL의 인증 토큰·코드를 자동 채택하지 않습니다. 남아 있는 기존 복구 링크는
`/admin/help/`에서 요청한 브라우저의 verifier를 가진 PKCE 코드만 명시 교환하고 실제 복구 AMR을 다시 검사합니다.
새 이메일 발송 양식·이메일 초대는 제공하지 않습니다. 도메인 변경은 [도메인 운영 안내](DOMAIN.md)를 참고합니다.

Free 플랜에서 유출 비밀번호 차단은 활성화할 수 없어 Auth Advisor 경고가 남을 수 있습니다.
기능 제공 조건은 [Supabase 공식 문서](https://supabase.com/docs/guides/auth/password-security)를 확인합니다.
요금제 변경은 운영자가 별도로 결정합니다.

## 콘텐츠와 이력

초안, 승인 대기, 발행을 구분합니다. 발행한 항목을 초안으로 돌리면 공개를 취소합니다.
정적 홈페이지는 다음 재구축 뒤 반영됩니다. 사진과 앨범이 필요하면 먼저 해당 미디어를 발행합니다.
선수 프로필은 UUID에 연결하고 Owner/Administrator가 승인합니다.
선수의 공개 동의를 철회하면 프로필은 DB에서 비공개로 바뀝니다.
공개 익명 조회는 허용된 열만 읽고, 승인자 UUID 등 내부 열은 현재 승인된 Owner/Administrator/Coach만 조회합니다.

변경 이력은 주체·테이블·항목·작업·변경된 필드 이름·시각을 남깁니다.
감사 로그에는 개인정보나 본문 전체를 복제하지 않습니다. V3 콘텐츠 복구는 기사·미디어·앨범·구단 안내의 내용을 별도 비공개 이력으로 보관하고 화면에는 최근 90일/항목별 30개를 표시합니다. 원본 이력은 자동 삭제하지 않습니다. 선수·연락처·출석·평가 자료는 이 대상이 아닙니다.
선수와 운영진은 삭제 대신 상태를 변경해 기존 UUID를 유지합니다.
반복 훈련 일정과 개별 일정의 변경도 같은 서버 감사 경로에 기록합니다. 실패하거나 롤백된 업무는 성공 이력으로 남지 않습니다.
과거에 작업자를 확인할 수 없는 기록은 그대로 유지하며 사람의 이름을 소급 지정하지 않습니다.

감사 이력의 보관 기간·정리 주기·승인 담당자는 운영자가 아직 확정하지 않았습니다.
기간 결정 전에는 임의 자동 삭제나 무기한 보관 정책을 새로 적용하지 않습니다.
정책 확정 시 목적과 접근 역할, 삭제 승인·실행 기록, 백업 보존 기간을 함께 문서화해야 합니다.
서비스 역할·DB 소유자의 직접 SQL은 업무 트리거의 행 변경은 잡을 수 있지만 Auth 세션이 없으면
사람의 작업자로 확인할 수 없습니다. 트리거 비활성화·DDL·외부 GitHub 배포와 AI 도구 실행은 이 업무 로그의 완전한 추적 범위가 아니며 서비스별 운영 이력을 함께 보존합니다.

## 백업과 검증

무료 프로젝트의 자동 백업을 전제로 하지 않습니다.
운영 담당자가 암호화된 저장 위치와 보관 기간을 정하고 DB 덤프와 미디어를 백업합니다.
비공개 선수 기록을 GitHub나 공개 Actions artifact에 넣지 않습니다.

마이그레이션 파일 버전은 원격 기록과 일치시키고 실행한 파일은 변경하지 않습니다.
DB 변경은 새 마이그레이션으로 추가하고 권한 검사를 통과한 뒤 적용합니다.
기존 단독 총괄의 미완료 프로필은 [최초 총괄 등록 절차](INITIAL_OWNER_SETUP.md)를 따릅니다. 일반 회원의 자기 승인과 분리한 유지보수 전용 경로이며, 명시적 요청과 안내 확인 없이 초기 등록을 완료하지 않습니다.
`npm test`만 입력하면 파트 목록과 사용법을 보여주며 실제 검사를 실행하지 않습니다. 수정한 업무는 `npm run test:members`처럼 `test:<파트 ID>`로 필요한 테스트용 빌드와 해당 검사를 실행합니다. 여러 파트를 함께 바꿨다면 `npm run test:prepare -- --parts members,players` 후 `npm test -- --parts members,players`로 선택합니다. 전체 회귀 검사는 명시적으로 필요한 경우에만 `npm run test:full`로 실행합니다. 검사 범위와 실제 Auth 실행 조건은 [기능별 검사 안내](PART_CHECKS.md)를 따릅니다.
실제 DB 검사는 supabase/tests/remote-permissions.sql로 실행하고 반드시 ROLLBACK합니다.
공개 API 검사에는 publishable key만 사용하며 Supabase Advisors에서 보안 상태를 확인합니다.

## 배포 보안

예약·수동 게시는 같은 SHA의 가장 최근 push 검사 시도에서 `Required part checks complete`가 성공한 뒤에만 진행합니다. 코드·예약·수동 검증은 서로 취소하지 않도록 실행 그룹을 나누고, 실제 게시는 직렬화한 뒤 잠금 안에서 최신 `main` 커밋을 다시 확인합니다. 이전 커밋의 산출물은 게시하지 않습니다. [검사와 게시 보호 절차](PART_CHECKS.md)를 참고하세요.

GitHub Pages의 Enforce HTTPS를 켭니다. HTTP의 `/`, `/admin/`, `/admin/help/`가 HTTPS로 이동하는지 배포 후 확인합니다.
빌드 HTML의 CSP는 실제 JS·CSS 해시, 같은 출처의 정적 파일, 관리 화면의 현재 Supabase 프로젝트만 허용합니다.
외부 스크립트·인라인 이벤트·eval·플러그인은 허용하지 않으며 관리자·복구 화면은 외부 Referer를 보내지 않습니다.
새 CAPTCHA 위젯 등 외부 스크립트를 도입할 때는 필요한 출처와 CSP를 별도로 검토해야 합니다.
GitHub Pages 정적 HTML의 meta CSP는 `frame-ancestors`, X-Frame-Options, HSTS, nosniff 같은 응답 헤더를 대체하지 않습니다.
이 헤더들은 응답을 제어하는 호스팅/CDN에서 별도 적용해야 하며 이번 변경에서 호스팅·요금제·DNS를 이전하지 않습니다.

오프라인 미리보기는 전체 생성·CSP 해시 검증이 성공한 뒤 폴더를 교체하므로 철회 경로가 남지 않습니다.
실패 때 이전 결과를 보존하고, OS가 복원을 막으면 백업 위치를 오류에 표시합니다.
교체 중 강제 종료 시 `.preview-export-*/previous`가 남을 수 있으므로 확인된 이전 결과를 복원하고 다시 생성합니다.
배포·미리보기에서 제거해도 이미 외부에 배포한 복사본을 회수할 수는 없습니다.
