# 2026-10-16 문구 정리와 프런트엔드 최적화

## 변경 범위

일본어 기본 UI와 한국어·영어 UI의 용어를 맞췄다. 공개 여부, 사이트 반영 여부, 승인 상태를 구분하고, 오류에는 가능한 다음 작업을 안내한다. 공개 페이지의 자료 없음 안내는 현재 상태만 설명하며 확인되지 않은 일정이나 준비 완료 시점을 약속하지 않는다.

- 공개 메뉴의 팀 명칭, 사진 탭, 참가 문의 목적, 빈 목록 안내를 일관되게 정리했다.
- 관리자의 공개·공개 취소·예약 공개, 최고 관리자 등 역할 표시를 통일했다. 역할 코드와 권한 판정은 유지한다.
- 작업 이력의 허용된 필드 54개를 업무 용어로 표시한다. 비공개·미등록 필드 마스킹은 유지한다.
- 브라우저 임시 저장에 실패하면 내부 예외 대신 번역된 안내를 표시하고 작성 중 입력을 보존한다. 실패를 저장 성공으로 표시하지 않는다.
- 번역 키 122개를 추가했으며 기존 키를 보존한다. 실명과 실제 콘텐츠는 자동 번역하지 않는다.

이 작업에는 DB 마이그레이션, Edge Function 배포, 계정/비밀번호/권한 변경이 없다. 기존 뉴스 본문·선수·일정·미디어·사진 원본과 미게시 소개 초안을 변경하거나 새로 게시하지 않는다.

## 자산 측정

기준은 main `b12d5b95414803562c7ffd5985e8f629da16306d`다. 같은 Node/의존성과 CMS·일정 비활성, 아이디 인증·기존 전환 경로 활성 설정으로 생성한 Astro 빌드의 HTML을 비교했다. JS는 페이지가 직접 읽는 모듈과 재귀 정적 import의 중복 없는 합계다. CSS는 외부 스타일과 HTML의 인라인 스타일을 합산했다. 단위는 원본 바이트이며 gzip은 각 파일을 별도로 압축한 합계 추정치다.

| 항목 | 이전 | 이후 | 변화 |
|---|---:|---:|---:|
| 공개 첫 화면 초기 JS | 155,630B | 6,899B | −95.57% |
| 공개 첫 화면 JS gzip 추정 | 45,059B | 3,164B | −92.98% |
| 관리자 화면 CSS | 89,619B | 51,011B | −43.08% |
| 도움말 화면 CSS | 85,838B | 47,230B | −44.98% |

공개 브라우저 코드가 전체 번역 사전을 가져오지 않도록 언어·URL 처리를 분리했다. 동적 문구 8개만 현재 언어로 HTML 속성에 안전하게 전달하며 번역 원본은 `src/data/locales/messages.json` 하나다. 추가되는 JSON은 이스케이프 전 JA 351B / KO 340B / EN 303B다. 관리자에는 전체 번역 함수를 명시적으로 전달하도록 타입 계약을 둔다.

관리자와 도움말은 공개 홈페이지용 카드·메뉴 스타일 대신 공통 기본 스타일만 읽는다. 키보드 포커스, hidden, 모션 감소 설정은 공통 기본 스타일에 유지한다.

새 안내와 기존 번역 키 보존으로 관리자 JS는 약 512KB에서 543KB로 증가했다. 관리자 JS와 CSS의 합계는 약 602KB에서 594KB로 소폭 감소했다. 모든 JS가 줄었다고 해석하면 안 된다. 위 수치는 실제 네트워크 전송량·실행 시간·Lighthouse 또는 Core Web Vitals 결과가 아니다.

## 검증

- `npm run check`: 76파일, 오류·경고·힌트 0.
- `npm run build`, `npm run export:preview`: 각각 32페이지 생성.
- `npm test`: SQL 719개 통과. 기본 빌드 JS 283개 통과, 아이디 인증 전용 29개는 별도 빌드에서 실행.
- 아이디 인증 활성 빌드의 실제 번들 회귀 검사 29/29 통과. 두 빌드에서 JS 312개 전체 통과.
- 공개 검색·필터·탭·사진 확대·언어 메뉴, 관리자 편집과 저장 실패, 실명 표시·승인·계정 복구 UI 회귀 검사를 포함한다. 서버 응답은 로컬 UI 테스트에서 대체한다.
- 브라우저 Storage의 실제 Error 객체로 실패를 재현하는 JA/KO/EN 3개 검사가 수정 전 실패하고 수정 후 통과했다.
- 공개 번들에 전체 사전이 없는지, HTML의 현재 언어 8개 문구, 누락 문구·손상된 JSON 대체 처리, 관리자/공개 CSS 분리를 검사한다.
- 마지막 한국어 용어 한 곳을 정리한 뒤 check/build/export 및 번역·런타임·스타일 검사를 다시 수행한다. 최종 PR CI가 전체 트리를 다시 검증한다.

실제 Android 기기와 현장 성능은 별도 측정이 필요하다. 배포 후 공개 경로·자산 응답과 공개/비로그인 관리자 화면을 확인하고 CI/배포 결과는 PR에 기록한다. 운영 계정의 자격 증명을 바꾸거나 실데이터를 저장하는 검증은 하지 않는다.

## 전환과 복구

별도 브랜치에서 검증하고 PR 검사 통과 후 main에 병합한다. 기존 GitHub Pages workflow로 정적 파일을 배포하며 데이터 전환은 없다. 문제가 생기면 이 PR을 revert해 다시 배포하거나 이전 성공한 Pages 배포의 소스로 재구축한다. 계정·DB·Edge Function은 이 작업의 복구 대상이 아니다.
