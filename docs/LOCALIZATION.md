# 홈페이지·CLUB OFFICE 언어 운영

## 언어와 주소

- 일본어 기본 주소는 `https://kansaiunited.com/`입니다. 기존 뉴스·선수 슬러그는 유지합니다.
- 한국어는 `/ko/`, 영어는 `/en/`이며 모든 공개 목록·상세 페이지를 정적 HTML로 생성합니다.
- 헤더의 JP·KO·EN 메뉴는 현재 페이지의 다른 언어로 이동합니다. 공개 페이지의 섹션 위치도 유지합니다.
- 관리자는 `/admin/?lang=ko` 또는 `?lang=en`으로 표시 언어를 선택합니다. 기존 세션 키·로그인·RLS·권한·서버 저장 필드는 그대로 사용합니다.
- 관리자 언어는 같은 브라우저에서 기억합니다. 인증 이메일은 `/admin/`으로 복귀하며, 인증 토큰을 언어 링크에 복사하지 않습니다. 도메인이 바뀌면 새 주소에서 다시 로그인합니다.
- 날짜의 표시 언어와 시간대는 별개입니다. 경기·훈련·예약은 모든 언어에서 JST 기준입니다.

## 번역을 편집하는 위치

`src/data/locales/messages.json`에서 일본어 원문 키의 `ko`, `en`을 함께 편집합니다. 메뉴·안내·오류·콘텐츠 번역을 한곳에서 찾을 수 있습니다. 문장의 `{0}`, `{1}`은 이름·숫자·시간 등을 넣는 자리이므로 번역문에서도 번호를 유지합니다. 영어 어순을 위해 문장을 잘게 나누지 않습니다.

등록된 공개 기사 3개, 구단·참여 소개, 앨범과 사진 설명의 한국어·영어 번역을 제공합니다. 원문을 Supabase에서 덮어쓰거나, 언어별로 기사 행을 복제하지 않습니다. 선수 UUID·슬러그·사진·공개 승인·동의 상태와 수치는 공통으로 유지합니다. 내부 선수 이름과 편집 필드의 원문은 선택 언어로 임의 변경하지 않습니다.

새 뉴스와 구단·참여 소개는 관리자 편집기의 日本語·한국어·English 탭에서 직접 작성합니다. 일본어 기본 필드와 같은 행의 `translations` JSON에 한국어·영어 제목·본문을 저장합니다. 뉴스는 요약과 사진 설명, 소개 페이지는 도입문도 각각 작성합니다. URL·사진·분류·예약·공개 설정은 공통입니다. 새 뉴스 번역에 코드 수정이나 수동 배포 요청이 필요하지 않습니다.

한국어·영어는 비워 두어도 되며, 일부만 작성한 번역은 초안으로 저장할 수 있습니다. 발행하려면 사용한 언어의 모든 항목을 완성해야 합니다. 예약 발행에서도 DB 검증을 다시 거칩니다. 미리보기에서 언어를 선택할 수 있고, 브라우저 임시 저장과 서버 수정 이력·복구에 번역이 포함됩니다. 저장 성공과 공개 사이트 반영은 별개이며 기존 정기 재구축 후 반영됩니다.

CMS에 작성한 번역을 사전보다 우선합니다. 번역을 비운 언어는 기존 자료의 사전 번역, 그마저 없으면 일본어 원문을 표시합니다. 기존 기사 3개의 번역은 사전을 통해 계속 제공됩니다. 확인되지 않은 자동 번역을 외부 서비스로 전송하지 않습니다. 앨범 설명·일정·메뉴 등 편집기에 언어 탭이 없는 항목은 기존 사전 방식을 유지합니다.

새로운 UI 문구는 공개 컴포넌트에서 `forLocale(locale)`의 `t()`, 관리자에서는 `text()` 또는 `format()`으로 표시합니다. 관리자 정적 HTML은 `data-i18n`, `data-i18n-aria-label` 등 지정된 문구만 번역합니다. 폼 입력값·사용자 데이터 전체를 훑어서 바꾸는 방식은 쓰지 않습니다.

## 화면과 검색

`LanguageSwitcher.astro`, `languages.ts`, `languages.css`가 언어 선택의 화면·키보드 동작·반응형을 담당합니다. `i18n.ts`는 허용 언어·URL·변수 치환·날짜 표시를 관리합니다. 공개 데이터의 번역은 `src/data/locales/content.ts`에서 허용한 문자열에만 적용합니다.

한국어·영어 HTML에는 해당 언어의 본문, 메타 제목·설명, 사진 대체 텍스트, canonical·hreflang·OG 언어를 포함합니다. 검색 대상과 내부 링크도 현재 언어로 생성합니다. 관리자 noindex와 공개 데이터의 익명 RLS 조회를 유지합니다.

## 검사

기존 `npm run check`, `npm run build`, `npm run export:preview`, `npm test`를 실행합니다. 번역 검사는 모든 공개 페이지의 동일한 기사 연결, 언어·메타데이터, 번역 누락, 사진·14명이라는 기존 기사 사실, 미정 경기, JST 날짜 경계, 인증 토큰 제외, 한국어 관리 화면에서 원문 저장·영문 DB 필드 유지, 초대 전용 로그인과 기존 복귀 주소를 확인합니다.

DB 검사는 격리된 메모리 PostgreSQL에서 수행합니다. 운영 DB에 테스트 기사·선수·일정을 생성하지 않습니다. 다국어 작성 확장은 추가 마이그레이션으로 구현하며 기존 RLS·Auth 설정은 유지합니다.
