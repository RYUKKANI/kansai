# V3 1단계 — 통합 일정

V2 UI 위에서 기존 경기와 훈련을 함께 조회하고 구단 행사를 추가합니다. 원본 UUID를 유지해 향후 출석·경기 기록과 연결할 수 있습니다.

- 월간·주간·월별 목록, 날짜 이동, 종류·공개 상태 필터, JST 표시
- 기존 경기/훈련 양식 공유, 행사 추가, 취소 상태와 미정 경기 안내
- 반복 훈련: 같은 요일·시간에 1~12주 간격, 최대 52회·1년 범위, 원자적 생성
- 회차 단독 수정 또는 시리즈의 모든 미래·미실시 회차 수정. 전체 수정은 개인 변경 회차도 포함하며 날짜 차이와 새 지속 시간을 적용합니다. 과거/완료 회차는 유지합니다. 반복 간격·회수 변경은 새 시리즈를 만들고 이전 미실시 회차를 취소합니다.
- 훈련·행사는 기본 비공개. 공개 체크한 날짜·제목·장소·공개 안내만 홈페이지로 전달합니다. 경기 공개는 기존 발행 절차를 사용합니다.
- 대시보드에 행사 포함, 홈페이지에 공개 일정 표시. 공개 데이터 전용 파생 테이블은 자동 동기화되며 수동 입력·클라이언트 쓰기가 금지됩니다.

## 적용 순서

1. V2 PR을 먼저 병합합니다.
2. 이 PR의 `club_office_schedule` 마이그레이션을 별도 개발 DB에서 검증합니다. 기존 마이그레이션을 재실행하거나 운영 데이터를 초기화하지 않습니다.
3. 운영 적용 승인 후 새 마이그레이션 하나를 적용하고 API 스키마를 갱신합니다. 관리자 화면은 기능 조회 결과가 있을 때만 새 메뉴와 열을 사용합니다.
4. GitHub 저장소 변수 `PUBLIC_SCHEDULE_ENABLED=true`를 설정하고 홈페이지를 재배포합니다. 15분 주기의 기존 정적 재빌드로 시간 경과와 공개 변경을 반영합니다. 정확한 시각의 실시간 배포를 보장하지 않습니다.

롤백은 먼저 공개 일정 변수를 false로 바꾸고 이전 프런트엔드를 배포합니다. 생성한 일정/출석 연결을 지우는 역마이그레이션은 사용하지 않습니다.

## 검증

PostgreSQL 격리 환경에서 반복 생성/개별 수정/전체 이동/동시 저장 충돌/생성 실패 전체 취소, Editor·Coach·비활성 사용자·익명 권한, 비공개 메모 제외, 공개 철회·취소·삭제 동기화를 검사합니다. JST 자정·윤년·월/연 경계와 달력 전환·반복 양식은 자동 UI 검사로 검증합니다. 운영 DB에는 테스트 자료를 만들지 않습니다.

다음 단계는 콘텐츠 자동 임시 저장, 예약 발행, 수정 이력과 복구입니다. 선수 관리 상세 모델과 자동화는 별도 설계 문서로 준비합니다.
