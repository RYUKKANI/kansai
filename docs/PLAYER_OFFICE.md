# 선수 관리 통합과 공개 콘텐츠 저장소

## 선수 화면

사이드바의 **선수 관리**가 선수 정보·동의, 사진, 공개 프로필의 공통 진입점입니다. 선수를 등록한 뒤 해당 행의 편집·선수 사진·공개 프로필 버튼을 사용합니다. 편집 창에서도 같은 선수의 세 항목을 전환할 수 있습니다. 미저장 내용이 있으면 전환 전에 확인합니다.

내부 선수 등록과 공개 프로필은 같은 UUID를 사용하지만 저장·승인 규칙은 분리합니다. 새 프로필에서는 선택 선수 UUID를 고정합니다. 등록만으로 선수 프로필을 공개하지 않으며, 기존 프로필 사진을 새 등록 사진으로 자동 덮어쓰지 않습니다.

Owner·Administrator는 선수 사진 창에서 파일 업로드, 초안 저장, 확인 후 사진 승인을 진행합니다. 초안 사진도 내부 선수에 연결할 수 있지만 홈페이지와 공개 저장소에는 표시하지 않습니다. 사진이 공개 승인된 뒤 공개 프로필에서 사진을 선택·승인합니다. 프로필·사진 동의와 공개 프로필 승인 규칙은 기존과 같습니다.

Coach는 기존 공개 승인된 선수 사진을 선택할 수 있습니다. 새 사진 업로드나 사진/공개 프로필 승인 권한은 추가하지 않습니다. Editor에게 내부 선수 관리 접근을 열지 않습니다. 한 화면으로 합쳐도 DB·Storage RLS를 변경하여 권한을 확대하지 않습니다.

사진 저장과 내부 선수 연결은 두 작업입니다. 다른 담당자의 동시 수정 등으로 연결에 실패하면 사진의 저장 성공과 연결 미완료를 구분해 알립니다. 최신 선수 정보를 열어 사진을 다시 연결할 수 있습니다.

## kansai-sub 자료 모음

사용자가 지정한 [RYUKKANI/kansai-sub](https://github.com/RYUKKANI/kansai-sub)는 공개 자료의 별도 저장소입니다. 승인된 글·번역·사진·앨범·소개·프로필·공개 일정을 약 15분 간격으로 모읍니다. GitHub 작업 대기 때문에 늦어질 수 있습니다.

기준 입력·승인은 Supabase입니다. 저장소의 파일을 수동으로 바꾸어 공개 승인을 우회하는 가져오기는 제공하지 않습니다. 홈페이지도 기존 공개 승인 자료를 읽습니다. 내부 명부, 연락처, 동의 기록, 권한, 감사 로그, 초안은 공개 저장소로 내보내지 않습니다.

공개 취소 자료는 저장소의 현재 파일에서 제거합니다. Git 과거 이력에 기존 공개본이 남을 수 있으며, 과거 이력 영구 삭제는 별도 승인 후 처리합니다. 기존 기사 사전 번역과 새 CMS 번역의 출처를 파일에 구분해 기록합니다.

## 유지보수 위치

- `admin.ts`: 공통 선수 진입점·세 양식 전환·미저장 경고·사진 연결.
- `admin-list.ts`: 한 명의 선수 행에서 사진·프로필 작업, 공개 프로필 상태 필터.
- 추가 SQL: Owner/Administrator의 내부 초안 사진 참조 허용. 공개 미디어와 프로필의 승인 규칙은 보존.
- `kansai-sub/scripts/public-content.mjs`: 공개 열 허용 목록, 사진 수집, 번역, 버전·무결성 검증.
- `kansai-sub/.github/workflows/sync-public-content.yml`: 정기 수집과 변경 파일 커밋.
