# 소속·권한 등급 운영 — 2026-10-16

## 세 등급의 권한

화면의 소속은 총괄·스태프·선수로 통일합니다. 담당 업무는 별도의 선택 입력이며, 업무 문구로 권한을 판단하지 않습니다.

| 소속 | 서버 값 | 허용 범위 |
| --- | --- | --- |
| 총괄 | `owner` | 전체 업무, 홈페이지 공개·공개 취소·공개 자료 변경, 가입 승인·반려, 계정·등급 관리, 기존 선수 연결 |
| 스태프 | `staff` | 뉴스·선수·일정·미디어·소개 자료 조회와 미공개 초안 작성·수정·삭제. 공개 자료는 읽기만 가능 |
| 선수 | `player` | 본인 계정, 연결된 본인 선수 정보의 허용 필드, 공개 일정 조회 |

승인 대기자는 본인 신청 상태만 조회합니다. 가입 화면의 희망 소속은 기본 선수이며 권한을 부여하지 않습니다. 총괄의 승인 양식도 실제 부여 등급의 기본값을 선수로 두고, 확인 후 별도로 선택합니다. 본인 승인·본인 권한 승격을 허용하지 않으며 마지막 활성 총괄을 보호합니다.

스태프의 제한은 버튼 숨김뿐 아니라 DB RLS와 업무 RPC·트리거에 적용합니다. 이미 공개된 행의 본문 수정, 공개 취소·삭제, 공개 일정 변경, 공개 자료에 영향을 주는 동의·사진 변경도 총괄 권한이 필요합니다. 스태프가 후속 편집을 맡아야 하면 총괄이 먼저 공개를 취소한 뒤 초안으로 넘깁니다. 예약 공개 승인·취소도 총괄이 처리하며, 자동 발행 시 승인자의 현재 권한을 다시 검사합니다.

선수는 업무 원본 테이블·다른 선수 정보·관계자 명부·감사 이력에 접근할 수 없습니다. `office_player_portal()`은 현재 세션의 계정과 연결된 선수에서 허용한 필드만 반환하고, 일정은 내부 메모가 없는 공개 일정만 사용합니다. 계정 UUID와 `player_id`는 별개이며 총괄이 기존 선수와 수동 연결·해제합니다. 미연결 계정은 미연결 상태를 표시하고, 가입·등급 변경·연결 때문에 선수 기록을 자동 생성하지 않습니다.

## 기존 계정과 감사 이력

Supabase Auth의 UUID·비밀번호와 기존 콘텐츠를 보존합니다. `admin_roles`의 기존 `owner`는 총괄로 유지하고, `administrator`·`editor`·`coach` 원본 행은 삭제·일괄 변경하지 않고 실행 시 `staff`로 정규화합니다. 새 권한 부여는 `owner`·`staff`·`player`만 받습니다. 과거 신청의 희망 소속을 추측해 채우지 않습니다.

과거 감사 로그의 작업자 UUID·이름·역할 스냅샷은 수정하지 않습니다. 새 변경은 서버가 확인한 현재 UUID·승인된 이름·실제 등급으로 기록하며, 등급·선수 연결 변경도 이유와 함께 기록합니다. 브라우저가 보낸 `actor_id`, 이름, Auth `user_metadata`를 권한이나 작업자 근거로 사용하지 않습니다. 비밀번호·토큰·불필요한 개인정보를 로그에 추가하지 않습니다.

정지·등급 회수는 이미 발급된 JWT를 쓰는 요청에서도 현재 DB 승인·권한·Auth 세션을 다시 확인합니다. 이번 변경에서 2단계 인증을 새로 추가하거나 강제하지 않으며, 기존 인증 요소의 보호는 유지합니다.

## 반영과 복구

1. 같은 Git 트리의 검사와 PR 검증을 마친 뒤 현재 계정·자료 집계와 활성 총괄 유지 여부를 확인합니다.
2. DB 업무 권한 migration `20261016140404_member_grade_permissions.sql`을 적용합니다.
3. DB 신청·계정·선수 연결 migration `20261016140416_member_grade_accounts.sql`을 적용합니다.
4. 희망 소속을 서버 예약으로 전달하는 `staff-auth` Edge Function을 반영합니다.
5. 세 등급 가입·승인·업무 화면을 배포하고 공개 주소와 API 제한을 확인합니다.

장애가 있으면 영향을 받는 가입·관리 작업을 중지하고 직전 검증 화면·Edge 버전으로 되돌립니다. 이미 적용한 DB의 공개 제한과 권한 검사는 유지합니다. 이전 화면에서 지원하지 않는 선수 화면이나 옛 역할 선택을 사용하지 않으며, 계정 삭제·재가입·자료 초기화로 복구하지 않습니다. 기존 활성 총괄의 UUID와 접근을 보존합니다. 총괄 접근 복구가 필요한 경우 기존의 권한 있는 프로젝트 관리자 확인 절차만 사용하고, 공개·서비스 클라이언트에 임의 복구 권한을 추가하지 않습니다.

## 검증 범위와 상태

직접 SQL/API 권한 우회, 위조 작업자·희망 소속, 미승인·정지·기존 JWT, 스태프 초안과 공개 제한, 선수의 타인 정보 차단, 수동 선수 연결, 마지막 총괄, 감사 기록·실패 롤백을 격리 데이터로 검사합니다. 기존 뉴스·선수·일정·미디어 회귀 검사와 `npm run check`, `npm run build`, `npm run export:preview`도 확인합니다.

구체적인 최종 검사 수와 결과·배포 버전은 PR에 기록합니다. 이 문서 작성 시 세 등급 변경의 Docker GoTrue·Mailpit 실제 인증 CI는 PR 실행으로 확인할 단계이며, 운영 배포 완료를 뜻하지 않습니다. 운영 실계정의 비밀번호·실명·권한을 시험 값으로 바꾸지 않습니다. PGlite 단일 연결 검사는 실제 네이티브 Auth나 여러 DB 연결의 잠금 경쟁을 대신하지 않습니다.

플랫폼 관리자가 직접 수행하는 DB·배포 작업은 일반 관계자 권한의 범위 밖입니다. 그 경로에서 확인할 수 없는 사람의 이름을 감사 작업자로 추정하지 않습니다. 보관 기간을 새로 정하거나 과거 로그를 일괄 삭제하지 않습니다.
