# 홈페이지·관리자 전체 점검 — 2026-10-16

## 검사 기준

운영 main `6609e5ca`에서 별도 브랜치를 만들고, 실제 운영 Supabase 프로젝트·배포 버전을 확인했습니다. 기존 계정·권한·콘텐츠·선수·감사는 초기화하지 않습니다. 운영 계정의 비밀번호·실명·MFA를 테스트 값으로 바꾸지 않습니다.

정상 입력 경로뿐 아니라 지연 응답, 창 복귀, 계정 교체, 업로드 중 취소, 기존 사진 참조, 역할과 MFA 조합을 격리 환경에서 재현했습니다. 수정 전 실패하는 회귀 검사로 확인한 문제를 수정합니다. 공개 페이지는 실제 주소에서 조회하고, 업무 저장·승인·삭제는 운영 자료를 수정하지 않는 자동 검사와 실제 Native Auth CI로 확인합니다.

## DB·인증 변경

추가 migration `20261016065018_staff_enrollment_mfa_and_scheduled_ban.sql`만 적용합니다. `office_enroll_identity`, `publish_due_content`, `can_read_audit`의 검사만 보완하며 계정·역할·콘텐츠 행을 일괄 갱신하지 않습니다. 기존 public wrapper와 private schema·함수 실행 권한을 유지합니다.

필수 명령은 `npm run check`, `npm run build`, `npm run export:preview`, `ADMIN_TEST_DIST=dist-legacy npm test`입니다. 별도 활성 빌드에서는 `staff-identity-app`, `staff-profile-state-app`, `staff-form-focus-app` 검사를 실행합니다. PR의 실제 GoTrue·Mailpit·RLS·복구 게이트웨이 CI도 건너뛰지 않고 확인합니다. 최종 실행 결과는 PR 체크를 기준으로 기록합니다.

## 반영·복구 순서

전체 검사와 실제 Native Auth CI가 통과한 같은 Git 트리를 확인한 뒤 추가 DB migration → `staff-auth` Edge Function → 정적 UI 순서로 반영합니다. 반영 전후 계정·권한·콘텐츠·감사 집계와 fingerprint를 비교하고, 새 함수 접근 권한·Advisor·익명 HTTP 차단·운영 페이지 제공을 확인합니다.

화면 또는 Edge Function 문제가 생기면 검증된 이전 버전으로 되돌릴 수 있습니다. DB의 강화된 권한 검사와 기존 자료·감사는 유지하며, 실패한 작업을 성공 이력으로 남기거나 자료를 임의 삭제하지 않습니다.
