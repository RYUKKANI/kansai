# 인증·권한·배포 보안 보강 — 2026-10-16

## 적용 범위

로그인·가입 화면은 아이디 기반을 유지하고 이메일 항목을 추가하지 않습니다.
가입은 구단의 `staff-auth` 서버에서 요청 제한·아이디 예약·승인 대기를 처리합니다.
기존 계정 UUID와 권한·비밀번호 검증이 Supabase Auth에 연결되어 있으므로 Auth는 유지합니다.
자체 비밀번호 저장·검증이나 기존 계정의 일괄 교체를 하지 않습니다.
새 2단계 인증 도입·등록·강제는 이번 범위에서 제외합니다. 기존 인증 수단에 대한 서버 검사는 유지합니다.

## 변경

| 대상 | 적용한 동작 |

| 일반 관리자 로그인 | SDK 생성 시 URL 인증 값 자동 채택을 끄고 기존 저장 세션을 유지 |
| 기존 복구 링크 | 전용 도움말에서 요청 브라우저의 verifier로 PKCE 코드만 명시 교환하고 실제 복구 AMR·UUID 재검사 |
| 공개 Auth 직접 가입 | 호스팅의 공개 가입 차단; 비밀번호 제공자는 유지하고 서버 Admin 가입 경로 사용 |
| 선수 공개 정보 | 익명 안전 열 공개는 유지; 내부 승인자 UUID는 현재 승인된 업무 역할만 조회 |
| 반복 훈련 일정 | 업무 변경과 같은 트랜잭션으로 서버 감사 로그 작성; 롤백 시 감사도 롤백 |

| CI | 공식 Actions 커밋 SHA 고정, 주간 업데이트 검토 PR, 실제 Auth 직접 가입 차단 검사 추가 |

기존 `profile_read_staff` 정책을 교체하고 `training_series`에 기존 감사 함수를 연결합니다.
계정·콘텐츠 행을 수정하거나 과거 감사 기록을 소급 생성하지 않습니다.

수정 파일은 `astro.config.mjs`, `package.json`, 공통 SecurityHead·공개/관리/도움말 head,

구체적인 파일 목록과 최종 Git 트리는 PR에서 확인합니다.

## 검사

- `npm run check`: 77파일, 오류·경고·힌트 0.
- `npm run build`, `npm run export:preview`: 각각 32페이지 성공.
- `npm test`: 기존 SQL 719개 검사와 신규 DB 시나리오 2개 통과. 기본 빌드 JS 297개 통과.
- 로그인 활성 빌드의 UI 검사: 35개 통과, 건너뜀 0. 기본 검사와 3개 중복 실행을 제외하면 JS 329개 검증.
- 세션 URL·DB 내부 열 조회·반복 일정 감사 검사는 수정 전 실패와 수정 후 통과를 확인.
- 미리보기 9개 회귀는 철회 경로, 입력 원본 보존, 실패 복원, CSP 승인 해시와 미승인 코드 거절을 확인.
- CSP 검사는 모든 실제 빌드 HTML의 정책·스크립트·스타일 해시를 비교. jsdom 자체는 CSP를 강제하지 않으므로 실제 배포 브라우저 동작도 별도로 확인.
- Docker가 없는 개발 실행 환경에서는 실제 GoTrue 검사를 실행하지 않음. PR의 `Native Auth integration` CI가 일회용 Supabase·Mailpit에서 직접 가입 거절, 무메일 서버 가입, 동일 UUID 로그인, 승인 전 RLS, 복구·권한 회수·감사를 검증.

최종 CI 실행 URL·결과, 운영 설정과 적용 후 확인 결과는 PR에 기록합니다.
운영 계정을 새로 만들거나 실계정의 비밀번호·실명·역할을 시험 값으로 바꾸지 않습니다.

## 복구와 남은 범위

화면 장애는 직전 검증 커밋을 되돌리는 새 PR로 복구합니다. 계정 삭제·재가입은 하지 않습니다.
DB 내부 정보 제한과 감사 트리거는 이전 화면과 호환되므로 화면 복구 시 유지합니다.
DB 적용은 단일 트랜잭션이며 실패 시 일부 정책만 반영하지 않습니다.
새 감사 트리거로 업무 저장이 실패하면 그 변경 역시 롤백됩니다. 원인을 수정하는 별도 마이그레이션을 검증해 적용하고 감사 로그를 일괄 삭제하지 않습니다.
호스팅 공개 가입 차단·HTTPS는 유지하고 서버 가입 경로의 가용성을 먼저 점검합니다.
미리보기 복원과 감사 보관 정책은 [운영 안내](OPERATIONS.md)를 따릅니다.

GitHub Pages HTML meta 정책은 HSTS·frame-ancestors·X-Frame-Options·nosniff·Permissions-Policy 응답 헤더를 설정하지 못합니다.
헤더 제어가 필요한 경우 별도 호스팅/CDN 구성이 필요하며 이번 변경에서 비용·도메인 경로를 임의 변경하지 않습니다.
HSTS preload나 모든 하위 도메인 적용도 임의로 등록하지 않습니다.
Free 플랜의 유출 비밀번호 차단 경고는 [Supabase 공식 문서](https://supabase.com/docs/guides/auth/password-security)에 따라 별도 운영 결정 사항입니다.
DB 관리자 직접 작업·DDL·외부 자동 배포·AI 실행 전체를 업무 감사 로그 하나로 완전히 추적할 수는 없습니다.
로그 보관 기간과 자동 정리 주기는 운영자가 정해야 하며 이번 작업에서는 삭제 작업을 추가하지 않습니다.
