# 관계자 이름 표시·실명 수정 버그 수정

## 원인과 결과

- 상단은 확인된 실명만 읽어, 실제 등록 이름을 저장해도 일반 안내 문구와 KU가 남았습니다. 서버의 확인된 실명 → 등록 이름 → 로그인 ID 순서로 표시하고 실명 미확인 배지를 별도로 둡니다. 이름은 번역하거나 HTML로 해석하지 않습니다.
- 내 계정은 미확인 이름에도 정정 신청만 제공했습니다. 초기 프로필이 미완료면 그 신청도 거부되고, 유일한 Owner는 자기 신청을 승인할 수 없었습니다. 미확인 이름의 본인 수정과 확인된 실명의 승인 정정을 구분합니다.
- Owner 계정 창의 저장은 성공 응답의 대상과 값을 확인하지 않았습니다. 실제 저장된 UUID·아이디·실명이 요청과 일치할 때만 성공으로 표시합니다. 미완료 기존 계정은 실명 없이 아이디만 수정할 수도 있습니다.
- 저장 후 상단·목록 갱신 실패가 저장 실패로 안내되거나 예전 이름을 남길 수 있었습니다. 확정된 저장과 후속 조회 실패를 구분하고 본인 계정 표시는 별도로 다시 읽습니다.
- 프로필 등록 버튼이 목록 갱신 후 사라지거나 예전 이름을 초기값으로 쓸 수 있었습니다. 현재 계정의 최신 등록 상태로 버튼을 유지·제거하고, 필요한 등록 항목을 안내합니다.
- 포커스 복귀·Auth 갱신이 겹치거나 다른 UUID로 바뀌는 경우, 오래된 응답이 현재 화면을 덮어쓰지 못하게 합니다. 로그아웃 시 이름·아바타·내부 화면을 정리합니다.

## DB 변경

`staff_unverified_name_edit` 추가 migration만 적용합니다. 기존 migration·계정·권한·콘텐츠·과거 이력은 수정하거나 초기화하지 않습니다.

새 공개 RPC는 `office_update_unverified_name(p_real_name, p_reason)`입니다. 대상 UUID나 확인자를 입력받지 않으며 실제 호출자 `auth.uid()`의 미확인 이름만 수정합니다. 승인된 현재 역할과 실제 남아 있는 Auth 세션이 필요하며 Owner MFA 정책을 유지합니다.

- `office_account_state`에 `name_edit_mode`, `profile_enrollment_pending`, `can_edit_real_name`을 추가합니다.
- UUID·로그인 ID·역할·승인·실명 확인·소속·동의·등록 완료 여부는 유지합니다.
- 확인된 자기 실명의 직접 수정은 거부합니다. 기존의 다른 Owner에 의한 확인·정정 절차를 유지합니다.
- 미확인 이름 수정과 충돌하는 이전 정정 신청은 `withdrawn`으로 취하합니다. 확인자·심사 시각을 만들지 않습니다.
- 이름 수정·신청 취하·감사는 같은 트랜잭션입니다. 감사 실패 시 함께 롤백합니다. 이름 원문은 감사 변경 전후 값에 넣지 않고 서버 작업자 UUID를 기록합니다.
- 익명과 service_role에는 새 RPC 실행 권한을 주지 않습니다. 브라우저가 전달한 metadata·작업자·확인자·다른 대상은 권한 근거가 아닙니다.

## 검증 범위

새 SQL 검사는 미확인 기존 Owner, 동명이인·국제 문자 이름, 승인 대기·정지·회수된 세션·MFA, 자기 확인 우회, 감사 롤백을 다룹니다. UI 검사는 세 언어, 이름·아바타·확인 배지, 실제 저장 응답, 실패와 중복 제출, 상단/등록 버튼 갱신, 로그아웃·지연 응답을 다룹니다.

실제 Native Auth CI에도 기존 UUID의 미완료 Owner 이름 수정, 권한·확인 상태 보존, 작업자 위조 차단, 비밀번호 복구 후 이름 유지 검사를 추가합니다. 운영 계정의 이름을 테스트 값으로 바꾸지 않습니다.

필수 실행은 `npm run check`, `npm run build`, `npm run export:preview`, `ADMIN_TEST_DIST=dist-legacy npm test`, 플래그 활성 빌드의 `tests/staff-identity-app.test.mjs`와 `tests/staff-profile-state-app.test.mjs`, 실제 `npm run test:auth:native` CI입니다. 최종 성공 결과는 PR 체크에서 확인합니다.

## 배포·복구

같은 트리의 전체 검사·실제 Auth CI 성공을 확인한 뒤 새 migration → 정적 관리자 UI 순서로 반영합니다. 이번 수정은 Edge 비밀번호 처리 코드를 바꾸지 않습니다.

문제가 생기면 정적 UI를 검증된 이전 버전으로 되돌릴 수 있습니다. DB의 추가 함수·취하 상태·이미 확정된 이름과 감사는 유지하고, 임의 삭제나 과거 이름으로의 일괄 복원을 하지 않습니다. 새 UI의 `name_edit_mode`를 사용하는 동안 DB 함수를 제거하지 않습니다.

이 수정은 실명 확인을 자동 완료하지 않습니다. 소속·담당 업무와 안내 확인이 미완료인 계정은 별도의 본인 등록을 마쳐야 합니다. 외부 플랫폼에서 수행한 직접 DB 작업이나 구단 전체의 별도 관리 기능을 모두 검사했다고 해석하지 않습니다.
